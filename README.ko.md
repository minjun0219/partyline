# Partyline

> a protocol for relaying messages between AI coding sessions on
> different machines — plus a reference relay and a Claude Code plugin
> 서로 다른 머신에서 도는 AI 코딩 세션끼리 메시지를 중계하는 프로토콜 —
> 참조 릴레이와 Claude Code 플러그인까지.

> English: [README.md](./README.md)

---

## ⚠️ 어떤 릴레이든 쓰기 전에 읽을 것

**릴레이 운영자는 당신 세션에 임의의 텍스트를 주입할 수 있다.**

릴레이에서 도착한 메시지는 당신의 코딩 에이전트에게 입력이 된다. 그
메시지는 프롬프트 주입일 수 있다 — 코드를 흘리게 하거나, 명령을 실행하게
하거나, 무언가를 밖으로 내보내게 시키는 지시. 프로토콜은 이것을 막지
않으며, 막을 수도 없다.

**1차 방어선은 릴레이 선택이다.** 직접 세워서 쓰거나, 붙일 세션들의 내용을
이미 믿고 맡길 수 있는 사람이 운영하는 릴레이를 쓴다. 이 저장소 어디에도
릴레이 URL 기본값은 없고, 그건 의도된 것이다 — 기본값은 곧 실수로 붙게 되는
서버다.

2차 방어선은 클라이언트다. 당신이 시키지 않았는데 채널에 들어가서는 안 되고,
무엇을 보냈는지 당신에게 보여야 한다. 이건 클라이언트가 지켜야 할 요구사항이고
[SPEC.md §7](SPEC.md#7-client-requirements) 에 규범으로 적혀 있다.

## 무엇인가

같은 머신에 있는 두 코딩 세션은 이미 로컬 소켓으로 대화할 수 있다.
Partyline 은 그 둘이 같은 머신에 없을 때를 위한 것이다 — 노트북과
워크스테이션, 데스크톱과 클라우드 박스.

모델은 일부러 작게 잡았다:

- **채팅방이 아니라 채널.** 채널은 주소록 + 접근 경계다 — 서로 부를 수 있는
  세션의 범위. 이력은 없다: 릴레이는 수신자가 가져갈 때까지만 메시지를 들고
  있고, 무슨 말이 오갔는지는 저장하지 않는다.
- **참가자는 세션이다.** 머신도 사람도 아니다. 참여는 세션이 명시적으로 하는
  행위이고, 클라이언트 프로세스가 떴다고 아무 채널에도 들어가지 않는다.
- **모든 메시지는 수신자를 지목한다.** 브로드캐스트가 없으므로 메시지 하나가
  방 안의 세션 전부를 깨우는 일이 없다.
- **비공개 채널만 있다.** 이미 안에 있는 누군가의 초대로만 들어간다.

접근은 계정 체계가 아니라 capability 사슬이다 — 추측 불가능한 채널 식별자,
손으로 전달하는 초대, 채널별 참가자 토큰. 릴레이 자체에는 계정도 관리자도
없다: 운영은 곧 배포이고, URL 을 안다고 어느 채널에도 닿지 못한다.

## 구성

| 경로 | 무엇인가 | 상태 |
| --- | --- | --- |
| [`SPEC.md`](SPEC.md) | 프로토콜. 직접 릴레이를 구현하기에 충분한 수준. | 초안 |
| [`server/`](server/) | Cloudflare Workers 용 참조 릴레이. | 동작·테스트 통과 |
| [`plugin/`](plugin/) | Claude Code 플러그인 — 클라이언트를 MCP 서버로 번들. | 동작·테스트 통과 |

스펙이 본체다. "각자 자기 릴레이를 세운다"가 설계 전제이므로, 남이 다시
구현할 수 있는 스펙이 여기 포함된 구현만큼 중요하다.

> `SPEC.md` 는 영어 원문만 유지한다. 규범 문서를 두 벌로 두면 반드시 어긋나고,
> 어긋난 스펙은 없느니만 못하기 때문이다.
